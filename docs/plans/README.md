# Historical implementation plans

This directory preserves implementation plans created before the current
Go/VPS refactoring-program plan inventory. They are historical execution
records, not current architecture or project tracking.

Before reusing a plan:

1. Find the related design under `../designs/`.
2. Check the current implementation and GitHub Issue state.
3. Revalidate dependencies and external API guidance.
4. Create a new plan only when the remaining work needs additional sequencing
   or verification detail.

GitHub Issues own work state. Do not update checkboxes in these files as a
parallel backlog. Preserve useful decisions in design documents and remove the
temporary plans during the final refactoring cleanup.
